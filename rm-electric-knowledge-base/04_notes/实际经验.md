## 2026-07-18 - BMI088 标定 Flash 写入失败（PGSERR）

> 日志系统使用见 [[../../02_code_twin/utils/ulog]]。

#### 现象

`BSP_FLASH_Write_Buffer` 写入 Flash 失败，`FLASH->SR = 0xC0`（PGSERR + PGPERR），HAL 返回 `HAL_ERROR`。

#### 调试过程

1. 27 年代码初始化阶段写入直接报错，但写了一个**检测线程**放到调度器启动后运行，发现线程级写入是正常的
2. 翻出 26 年代码对比，26 年初始化阶段写入正常，程序也能跑
3. 单步调试 26 年代码，结果初始化阶段也报错了——和 27 年一样的问题
4. 由此确认：**J-Link 单步调试干扰了 Flash 控制器时序**，导致"单步失败、全速成功"的两难局面

#### 更高效的方案

意识到逐行调试不可靠后，改用 **AI 读代码 + 日志插桩 + 全速运行** 的方式：

- 把知识库喂给 AI，让 AI 理解完整调用链
- AI 在 `main.c` 各 `MX_xxx_Init` 后、`robot_init.c` 的 BSP/MODULE/APP Init 之间插入 `FLASH->SR` 检查日志
- 全速运行后分析日志：进入 `Robot_Init` 时 SR 干净，到 BMI088 调 Flash 时 SR 已脏——问题出在 BSP_Init 内部某个 MX_Init 弄脏了 Flash 标志位

#### 根因与修复

BSP_Init 阶段某个 MX_Init（疑似 ADC DMA 或 SPI DMA 中断）把 `FLASH->SR` 弄脏了，脏标志残留到标定时。`FLASH->SR` 错误标志是**黏着的**，不清除会持续影响后续操作。

修复：在 `BSP_FLASH_Erase_Sector` 和 `BSP_FLASH_Write_Buffer` 入口加标志清除：

```c
__HAL_FLASH_CLEAR_FLAG(FLASH_FLAG_PGSERR | FLASH_FLAG_PGPERR);
```

 ## 2026-07-25 自研小c板的配置过程

```
Project Location: E:/STM32project/rm_2027/mas_embedded_threadx-f103/board
```

| 内容 | 路径 | 说明 |
|------|------|------|
| Inc/ | `board/105_rc/Inc/` | 外设头文件 |
| Src/ | `board/105_rc/Src/` | 外设源文件 |
| Startup/ | `board/105_rc/Startup/` | `startup_stm32f105xx.s` |

### 二、外设配置

#### SYS

| 配置项 | 值 |
|--------|------|
| Debug | Serial Wire |
| Timebase Source | TIM1（SysTick 让给 ThreadX） |

#### RCC — HSE: Crystal/Ceramic Resonator

#### IWDG — 启用（代码内部有耦合）

#### TIM3 — PWM（PC6-9, 4路, Prescaler=71, Period=999 → 1kHz）

#### CAN — 1MHz（Prescaler=9, BS1=2, BS2=1, 启用RX中断）

#### I2C1 — Fast Mode

#### SPI1 — 启用，参数默认

#### UART4 — SBUS（100000 baud, 8N1, RX DMA, RX 中断）

| 引脚 | 功能 |
|------|------|
| PC11 | UART4_RX（硬件反相电路输出端） |
| PC10 | UART4_TX（不接） |

#### NVIC — 取消 System Tick 和 PendSV 的生成

### 三、适配 CMake 构建

CubeMX 第一次生成时自动创建了 `CMakeLists.txt`、`CMakePresets.json` 和 `cmake/stm32cubemx/CMakeLists.txt`。我们在此基础上提取板级差异，链接到公共构建逻辑。

**关键：** 后续 CubeMX 重新 Generate Code 只会覆盖 `Inc/` + `Src/` + `Startup/`，不会动 `cmake/`、`CMakeLists.txt`、`CMakePresets.json`。

#### 3.1 板级工具链 — `cmake/gcc-arm-none-eabi.cmake`

从已有板复制，改 MCU 差异参数：

| 参数 | F105RC (M3) | F407 (M4) | H723 (M7) |
|------|-------------|-----------|-----------|
| `-mcpu` | `cortex-m3` | `cortex-m4` | `cortex-m7` |
| `-mfpu` | 无 | `fpv4-sp-d16` | `fpv5-d16` |
| `-mfloat-abi` | 无 | `hard` | `hard` |
| 链接脚本 | `STM32F105xx_FLASH.ld` | `STM32F407xx_FLASH.ld` | `STM32H723xx_FLASH.ld` |

#### 3.2 板级 CMakeLists.txt — 提取差异，链接公共逻辑

CubeMX 生成的根目录 `CMakeLists.txt` 包含所有 `add_subdirectory` 和 `target_link_libraries`。我们把它替换为简化版，只保留板级差异，公共逻辑交给 `board_common.cmake`：

```cmake
cmake_minimum_required(VERSION 3.22)
project(base)

set(THREADX_ARCH cortex_m3)        # 根据 MCU 改
set(BSP_USB_ENABLE OFF)            # 无 USB 的板关掉
include(${CMAKE_CURRENT_SOURCE_DIR}/../../cmake/board_common.cmake)
```

#### 3.3 CMakePresets.json

CubeMX 生成的预设配置，改 `toolchainFile` 路径指向板级工具链：

```json
{
    "version": 3,
    "configurePresets": [
        {
            "name": "default",
            "hidden": true,
            "generator": "Ninja",
            "binaryDir": "${sourceDir}/build/${presetName}",
            "toolchainFile": "${sourceDir}/cmake/gcc-arm-none-eabi.cmake",
            "cacheVariables": {}
        },
        {
            "name": "Debug",
            "inherits": "default",
            "cacheVariables": {
                "CMAKE_BUILD_TYPE": "Debug"
            }
        },
        {
            "name": "Release",
            "inherits": "default",
            "cacheVariables": {
                "CMAKE_BUILD_TYPE": "Release"
            }
        }
    ],
    "buildPresets": [
        {
            "name": "Debug",
            "configurePreset": "Debug"
        },
        {
            "name": "Release",
            "configurePreset": "Release"
        }
    ]
}
```

**`${sourceDir}` 指向 `board/105_rc/`，`toolchainFile` 路径相对于它。**

#### 3.4 `cmake/stm32cubemx/CMakeLists.txt`

CubeMX 生成的构建入口，包含 HAL 驱动源文件列表、头文件路径和编译宏。后续我们手动维护 HAL 源文件列表（加/减外设对应的 `.c` 文件）。CubeMX 重新生成不会覆盖这个文件。

### 四、配置 tasks.json

```json
{
    "label": "Build 105_rc",
    "type": "shell",
    "command": "powershell",
    "args": [
        "-Command",
        "cmake -S ${workspaceFolder}/board/105_rc -B ${workspaceFolder}/build/105_rc/Debug --preset Debug -G Ninja;",
        "if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE };",
        "cmake --build ${workspaceFolder}/build/105_rc/Debug --config Debug -j 20;",
        "if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE };",
        "Copy-Item -Path ${workspaceFolder}/build/105_rc/Debug/compile_commands.json -Destination ${workspaceFolder}/build/compile_commands.json -Force;",
        "Copy-Item -Path ${workspaceFolder}/build/105_rc/Debug/base.elf -Destination ${workspaceFolder}/build/105_rc.elf -Force"
    ],
    "problemMatcher": [],
    "group": "build"
}
```

### 五、补回 ThreadX 入口

CubeMX 重新生成会覆盖 `Src/main.c`，每次生成后补：

```c
int main(void) {
    HAL_Init(); SystemClock_Config(); MX_GPIO_Init();
    // ...
    tx_kernel_enter();    // ← 补
    return 0;
}

void tx_application_define(void *first_unused_memory) {
    // ← 补，ThreadX 初始化入口
}
```

### 六、编译验证

VS Code 按 `Ctrl+Shift+P` 选对应任务，或命令行：

```bash
cmake -S board/105_rc -B build/105_rc/Debug --preset Debug -G Ninja
cmake --build build/105_rc/Debug --config Debug -j4
```

#### 常见问题

| 报错 | 原因 | 解决 |
|------|------|------|
| `#error please define HAL_PCD_MODULE_ENABLED` | USB 相关代码编译失败 | `BSP_USB_ENABLE OFF`（已配置） |
| `undefined reference to 'huart6'` | `robot.cmake` 中 UART 映射不对 | 改 `robot.cmake` 的 UART 号 |
| `ThreadX 不运行` | CubeMX 覆盖了 `main.c` | 补回 `tx_kernel_enter()` |
